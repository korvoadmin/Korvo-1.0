# Minimum gates for the first non-money closed beta

Current decision: **NO-GO**. Target: 10 customers +10 professionals, invitation-only,
Atlanta metro, exact owner-approved lower-risk independent project categories, no real
money. Employee staffing is potential Korvo 2.0 scope, not beta work. This phase map
qualifies the authoritative KORVO_MASTER_LAUNCH_CHECKLIST.md; it does not replace its 144 IDs.

## Required before any invitations

1. Qualify a protected durable database backup and managed recovery/operator path,
   including applicable Storage bytes/configuration/role-secret handling. Current plan
   is Free; available tools expose no retained-backup/PITR reader or rehearsal interface.
   A restore mutation endpoint is not usable recovery evidence. No purchase authorized.
2. Approve exact A6 alternate (462 statements/seven packages) only after recovery,
   fresh drift/permission checks and explicit founder authorization. Genuine hosted
   customer/pro/support/owner/anonymous acceptance follows the authorized rollout.
3. Approve D6 exact category/geographic allowlist; D7 legal/privacy/retention versions,
   consent and staffed support/contact operation; D4 verified founder/MFA/recovery;
   D11 roster, test-activity limits and success/stop criteria. Define physical-service
   versus usability-only activity so qualified legal/insurance review matches scope.
   No business/legal decision is made by code or this document.
4. Review A11 core +discovery guards +independent server checkout prohibition. Protected
   populated recovery, default-off/fail-closed configuration, 10+10 admission, current
   assent, privacy/notifications and support tests must pass in a qualified environment.
   No participant is enrolled/invited by this engineering session.
5. If completion-photo workflows are enabled, separately approve the narrowed A10
   evidence-only package pinned in LAUNCH_RELEASE_MANIFEST.json. It does not need new
   refund/ledger/reconciliation schemas. Storage-owner-capable creation/rollback and
   actual Edge decoding/upload/private URL tests remain unqualified. Keep uploads off
   if their required backend is absent; never silently waive required evidence.
6. Approve the exact A8 frontend manifest and compatible release sequence, then verify
   served bytes, real signup/confirmation/resend/login/reset callbacks and one-use/reset
   behavior, current approved terms, all role boundaries and the full admitted journey.
   Real Auth email, quote-form UI and hosted Storage acceptance are not yet complete.
7. Complete support/incident/containment drill and named operator coverage. Obtain a
   separate explicit final invitation/go decision AFTER the above gates actually pass.

A safe release sequence needs a composed, separately reviewed change plan; no production
operation is authorized here. A6/A8/A10/A11 are separate scopes, not one blanket approval.

## Not prerequisites to this simulated cohort

paid membership Billing; provider settlement/reserve/funds-aging policy; actual $112
refund-allocation correction or $560 review disposition; payroll/staffing/agency/EOR
features. Preserve those tasks and holds for later money/public launch; never route
employee wages through contractor Connect or mark simulation paid/provider-verified.
